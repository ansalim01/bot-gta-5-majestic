# Сопровождение проекта

[← Вклад в проект](../CONTRIBUTING.md)

## Как принять pull request

1. Откройте PR и прочитайте описание. На вкладке **Files changed** проверьте
   итоговые изменения, особенно игровой ввод, тайминги и workflow.
2. Если GitHub ожидает разрешения для первого PR из внешнего fork,
   после просмотра изменений нажмите **Approve and run workflows**.
   Это запускает тесты и само по себе не разрешает слияние.
3. Дождитесь зелёных `checks (3.11)` и `checks (3.13)`.
   Внутри каждой проверки выполняются Ruff, проверка форматирования и pytest.
4. При проблемах оставьте замечания через **Review changes → Request changes**.
   Автор исправляет их в той же ветке.
5. Когда изменение готово, выберите **Review changes → Approve**.
6. Закройте завершённые обсуждения и выполните **Squash and merge**.

После новых коммитов прежнее одобрение сбрасывается. Если `main` изменился,
автору нужно обновить свою ветку и дождаться повторных проверок.

## Что защищает main

- `.github/CODEOWNERS` назначает `@ansalim01` владельцем всех файлов.
- Для участников обязательны одобрение владельца, обе проверки Python
  и закрытые обсуждения.
- Принудительная перезапись и удаление ветки запрещены правилами защиты.
- Автоматическое слияние не включено. Рабочие процессы имеют права чтения
  и не могут одобрять pull request.

У владельца-администратора остаётся возможность обходить правила для собственных
изменений. GitHub не позволяет автору одобрить собственный PR. Для чужих изменений
используйте обычный порядок просмотра и слияния, описанный выше.

## Где находятся настройки

- [Защита веток](https://github.com/ansalim01/bot-gta-5-majestic/settings/branches)
- [GitHub Actions](https://github.com/ansalim01/bot-gta-5-majestic/actions)
- [Pull requests](https://github.com/ansalim01/bot-gta-5-majestic/pulls)

Правила защиты настраиваются в GitHub: одного файла CODEOWNERS недостаточно,
чтобы блокировать слияние. Имена обязательных проверок должны совпадать с именами
job в workflow; при переименовании обновите и настройки защиты.

Подробнее: [защита веток](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches)
и [запуск workflow из fork](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/approve-runs-from-forks).
