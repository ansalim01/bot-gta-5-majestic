# Настройка сценариев

[← Установка и первый запуск](../README.md) · [Решение проблем](troubleshooting.md)

Все команды ниже выполняются в **PowerShell из папки проекта** после установки
по README. Используется Python из `.venv`; активировать окружение не требуется.

## Личные настройки

Для большинства изменений достаточно панели. Расширенные параметры можно
переопределить в личном YAML, сохранив общий файл проекта без изменений.

| Сценарий | Общие значения | Личные изменения |
| --- | --- | --- |
| Рыбалка | `config/fishing.yaml` | `config/user/fishing.yaml` |
| Качалка | `config/gym.yaml` | `config/user/gym.yaml` |
| Еда и вода | `config/sustenance.yaml` | `config/user/sustenance.yaml` |
| Блэкджек | `config/blackjack.yaml` | `config/user/blackjack.yaml` |
| Шахтёр | `config/miner.yaml` | `config/user/miner.yaml` |

Порядок ручного изменения:

1. Остановите сценарий и полностью завершите панель через меню в трее.
2. Откройте нужный личный файл текстовым редактором. Если его нет — создайте.
3. Укажите только изменяемые поля, сохранив отступы и кодировку UTF-8.
4. Запустите панель заново и проверьте значения. Уже открытая панель хранит старые
   значения редакторов и при сохранении может записать их поверх ручных изменений.

Например, это **полное содержимое минимального** `config/user/fishing.yaml`:

```yaml
fishing:
  target_fish_count: 20
```

Такой файл меняет только цель улова; остальные значения берутся из общего YAML.
Если файл уже содержит раздел `fishing`, добавьте поле в него, а не создавайте второй
раздел с тем же именем. Панель сохраняет в личный файл и другие свои настройки.

Пишите `true` и `false` без кавычек, числа — числами, используйте пробелы вместо
табуляции. Например, `auto_action: "false"` — строка и будет отклонена панелью.
Ошибка чтения или проверки блокирует сохранение и запуск соответствующей страницы.

Чтобы вернуть общие значения, при закрытой панели удалите нужные поля из личного
файла. Для полного сброса профиля сначала сохраните его копию вне проекта, затем
уберите соответствующий личный YAML. Общий файл в `config/` оставьте на месте.

## Запуск из панели и из консоли

| Способ | Когда бот начинает работу |
| --- | --- |
| Кнопка «Запустить» в панели | Сразу после запуска процесса; дополнительно нажимать F9 не нужно |
| Команда `main_*.py` или `main.py` | После **F9**, пока консольная программа работает |

В обоих случаях F9 ставит на паузу/продолжает, F10 останавливает сценарий.
После F10 для новой сессии нажмите «Запустить» в панели либо повторите консольную
команду. Запускайте один способ за раз: панель не управляет отдельно открытым ботом.

Консольные рыбалка, качалка, еда/вода и блэкджек запрашивают UAC при необходимости.
Для старого шахтёра `main.py` автоматического запроса UAC нет: при необходимости
запускайте его из PowerShell с правами администратора.

## Рыбалка

Перед запуском подойдите к месту ловли, подготовьте снаряжение и дождитесь
приглашения начать рыбалку через E. Бот подтверждает уже выбранное снаряжение;
выбор и покупку удочки, наживки и предметов подготавливает пользователь.
В общей конфигурации автоматический заброс включён.

```powershell
.\.venv\Scripts\python.exe main_fishing.py
```

При консольном запуске после F9 бот нажимает E на приглашении, ждёт экран
снаряжения и подтверждает его вторым E. Затем проходит заброс, поклёвку,
вываживание и сбор улова. При запуске кнопкой этот цикл включается сразу.

| Параметр | Значение |
| --- | --- |
| `fishing.target_fish_count` | Цель улова; `0` — без ограничения. После достижения цели сценарий завершается |
| `fishing.auto_cast` | `true` — автоматически начинать забросы; `false` — начало заброса вручную |
| `fishing.sustenance_enabled` | Проверять еду/воду перед забросом |
| `mode: cast_and_reel` | Полный цикл ловли на подготовленном месте |
| `mode: minigame_only` | Помощь в мини-игре; запуск и подготовка активности остаются пользователю |
| `reel.invert_pan_steer` | Поменять направление управления A/D при вываживании |

Для обслуживания еды/воды бот выходит из активности через Esc, использует
предметы и повторяет подготовку E → снаряжение → E. Если нужное действие
не удаётся подтвердить после повторов, возможна безопасная пауза. Проверьте
журнал, положение персонажа и предметы; после устранения причины продолжите F9.

Не включайте отдельный бот еды/воды параллельно: рыбалка уже использует этот сервис.
Маршруты к месту и продажа улова не входят в описанный здесь цикл на готовом месте.

## Качалка

Подойдите вплотную к уличному тренажёру. В инвентаре должны быть напиток и еда,
соответствующие шаблонам сервиса. Бот начинает упражнение через E и распознаёт
круглые подсказки W/A/S/D; перед новым подходом проверяет голод и жажду.

```powershell
.\.venv\Scripts\python.exe main_gym.py
```

В консоли нажмите F9 для начала. В панели используйте «Запустить».
Параметры распознавания и задержек находятся в `config/gym.yaml`.
Отладочный кадр при включённой записи — `logs/gym_live.png`.

## Еда и вода

Оставайтесь на основном игровом экране. По умолчанию сервис ищет **Cola**
и **батончик** по шаблонам из `config/templates/sustenance/`.
Он не покупает и не создаёт предметы; они должны уже лежать в инвентаре.

```powershell
.\.venv\Scripts\python.exe main_sustenance.py
```

В консоли начните работу F9. Проверка HUD выполняется раз в минуту;
**F8** запрашивает внеочередную проверку. На паузе запрос ждёт продолжения.
Без индикатора голода или жажды инвентарь не открывается — это нормальное поведение.

При потребности сервис открывает инвентарь через I, подтверждает его заголовок,
находит предмет в сетке и делает двойной клик. Для других предметов нужны
соответствующие изображения в списках `templates.water` и `templates.food`
в `config/sustenance.yaml` либо личном переопределении.

В рыбалке и качалке этот сервис встроен; отдельный процесс для них не запускайте.

## Блэкджек

Откройте игровой стол и заранее выберите сумму ставки в игре.
В панели укажите ту же сумму в поле «Размер ставки для отчёта».
Это поле нужно для расчётов и не переключает сумму на столе.

```powershell
.\.venv\Scripts\python.exe main_blackjack.py
```

В консоли программа ждёт F9. Кнопка панели сразу запускает работу.
В общей конфигурации включены автоматические ходы и ставки,
а лимиты сессии равны `0`, то есть отключены.

Для наблюдения без нажатий выключите в панели **оба** переключателя
«Автоматически нажимать» и «Автоматически ставить», либо используйте:

```yaml
# config/user/blackjack.yaml
blackjack:
  auto_action: false
  auto_bet: false
```

Ходы и автоставки независимы: выключение только `auto_action` не отключает ставки.
Автоматическая ставка подтверждает Enter уже выбранную в игре сумму.

| Параметр | Назначение |
| --- | --- |
| `blackjack.double_policy: basic` | Полная effective-48 EV-таблица даблов |
| `blackjack.double_policy: conservative` | Дабл ограничен твёрдыми 10–11 |
| `blackjack.double_policy: never` | Без даблов |
| `blackjack.split_enabled` | Разрешение сплита |
| `blackjack.risk.max_session_loss` | Лимит убытка; `0` отключает |
| `blackjack.risk.max_drawdown_from_peak` | Лимит потери от лучшего результата сессии; `0` отключает |
| `blackjack.risk.max_hands_per_session` | Максимум раздач; `0` отключает |

При сплите учитывается порядок Majestic: вторая показанная сумма, затем первая.
Отчёт хранит версию стратегии; результаты разных моделей следует сравнивать
раздельно. Модель стратегии и подсчёт карт не гарантируют прибыль.

## Шахтёр

Кнопка шахтёра в панели пока отключена. Существующий сценарий запускается отдельно:

```powershell
.\.venv\Scripts\python.exe main.py
```

После запуска нажмите F9. Настройки берутся из `config/miner.yaml`
и `config/user/miner.yaml`. **В общей конфигурации выбран `mode: full`**:
проверьте режим до запуска, если нужна только помощь в мини-игре.

| `mode` | Поведение |
| --- | --- |
| `minigame_only` | Пользователь перемещается и добывает; бот кликает жилы мини-игры |
| `walk_minigame` | Навигация и мини-игра |
| `full` | Цикл добычи с настроенной навигацией |

Для помощи только в мини-игре укажите:

```yaml
# config/user/miner.yaml
mode: minigame_only
```

Запись маршрутов и их назначение описаны в [README маршрутов](../config/routes/README.md).
Шаблоны и маршруты рассчитаны на конкретную игровую обстановку;
готовые записи не заменяют настройку под другое место.

## Запуск панели без консоли

После успешного обычного запуска можно использовать Python без консольного окна:

```powershell
.\.venv\Scripts\pythonw.exe .\GameBot.pyw
```

Двойной клик по `GameBot.pyw` выбирает Python, связанный с расширением `.pyw` в Windows.
Он может отличаться от `.venv`; тогда зависимостей в нём не окажется. При непонятной
ошибке вернитесь к `python.exe launcher.py` из `.venv`, чтобы видеть вывод консоли.

Для ярлыка на рабочем столе укажите:

| Поле | Пример для `C:\game-bot` |
| --- | --- |
| Объект | `"C:\game-bot\.venv\Scripts\pythonw.exe" "C:\game-bot\GameBot.pyw"` |
| Рабочая папка | `C:\game-bot` |
| Значок, при необходимости | `C:\game-bot\assets\gamebot.ico` |

В проекте также есть `tools/create_shortcut.ps1`. Он берёт `pythonw.exe` из `PATH`,
поэтому при установке в `.venv` проверьте, какой интерпретатор будет использован.
Ярлык хранит абсолютные пути; после перемещения проекта его нужно обновить.

## Монитор, калибровка и изображения

`screen.resolution` — базовое разрешение координат, `regions` — области интерфейса
в формате `[x, y, ширина, высота]`. Для обычного использования оставьте
1920 × 1080 и масштаб Windows 100%. Менять области нужно по сохранённому кадру.

В сценариях с `screen.force_monitor: true` поле `screen.monitor_index` выбирает
экран захвата: `1` — первый экран в списке захвата, `2` — следующий. Индекс не обязательно
совпадает с номером экрана в настройках Windows. Проверьте отладочный кадр.
При встроенном сервисе еды/воды захват задаёт основной сценарий рыбалки или качалки.

Пример проверки детекторов на **вашем полном скриншоте** `screenshot.png`,
положенном в папку проекта:

```powershell
.\.venv\Scripts\python.exe tools/test_fishing.py screenshot.png --no-gui
.\.venv\Scripts\python.exe tools/test_minigame.py screenshot.png --no-gui
```

Калибровка областей и создание шаблонов могут менять общие файлы конфигурации
или изображения. **До запуска сохраните копии нужных файлов.** Выберите нужную
команду, а не запускайте весь список подряд:

```powershell
.\.venv\Scripts\python.exe tools/calibrate.py screenshot.png --fishing
.\.venv\Scripts\python.exe tools/calibrate.py screenshot.png
.\.venv\Scripts\python.exe tools/test_minigame.py screenshot.png --extract --no-gui
.\.venv\Scripts\python.exe tools/extract_vein.py screenshot.png
```

В окне `calibrate.py` выделяйте область перетаскиванием мыши: N — следующая область,
S — сохранить, Q — выйти. **При выходе через Q конфигурация тоже сохраняется.**
Имена выбираемых областей видны в окне и консоли. Без `--fishing` изменяется
конфигурация шахтёра, с этим флагом — рыбалки.

Не запускайте инструменты для живого окна одновременно с работающим ботом.
Рабочие ограничения тайминга рыбалки предназначены
для разработчиков и описаны в [правилах тайминга](fishing-timing.md).

## Диагностические файлы

Все пути ниже указаны от папки проекта. Файлы появляются только после работы
соответствующего сценария и при включённых параметрах записи.

| Файл | Содержимое |
| --- | --- |
| `logs/fishing_sessions/latest_summary.txt` | Последний текстовый отчёт рыбалки |
| `logs/fishing_sessions/latest_summary.json` | Тот же отчёт для панели и обработки программой |
| `logs/blackjack_sessions/latest_summary.txt` | Последний отчёт блэкджека |
| `logs/blackjack_live.png` | Область распознавания блэкджека |
| `logs/gym_live.png` | Подсказка качалки |
| `logs/sustenance_inventory.png` | Последний диагностический кадр инвентаря |

JSONL рядом с отчётами содержит события сессий. Страница «Журнал» показывает
сообщения текущего сеанса панели. Перед разбором ошибки сверяйте идентификатор
сессии в отчёте: при выключенной телеметрии там может остаться старый файл.
